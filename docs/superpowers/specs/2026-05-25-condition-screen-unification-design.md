# Design: コンディション画面とToday体調入力の統一

**Date:** 2026-05-25  
**Status:** Approved

## 背景と課題

- `/self-care` は現在プレースホルダー表示で、実際の入力UIが見えない
- 履歴グラフUIは存在するが、入力導線がユーザー視点で不明瞭
- Today の体調は3段階、Self Care 側は5段階（身体/心）でモデルが分かれている

## 目標

1. 下部ナビの導線として「コンディション」画面を有効化する
2. コンディション画面で、次を入力・保存できるようにする
   - 身体スコア（1..5）
   - 心スコア（1..5）
   - 身長・体重・体脂肪率
3. Today でも同じ体調データを編集できるようにし、Today はショートカットとして機能させる
4. 体調データ保存先を `daily_wellness` に統一し、表示整合を保つ

## 非目標（今回やらないこと）

- セルフケア実施ログ（回数/分数/実施可否）のUI再投入
- セルフケア自由メモUIの再投入
- 履歴画面への新規入力フォーム追加

## 変更方針

### 1) 画面導線

- `/self-care` をプレースホルダーから本画面へ差し替える
- 表示ラベルは「セルフケア」ではなく「コンディション」基調へ変更
- ナビ構成は維持し、ラベルのみ更新

### 2) 入力UI範囲

- コンディション画面は以下のみ表示
  - 身体/心スコア
  - 身長/体重/体脂肪率
- 既存のセルフケアログ入力行とメモ入力は非表示化（コード資産は温存）

### 3) データ統一

- 体調入力の保存先は `daily_wellness` に一本化
- Today の体調入力も同じ保存先を使う
- `daily_condition`（3段階）依存は段階的に解消する
- 指標値は引き続き `daily_metrics` を利用する

## コンポーネント/責務

- `src/app/self-care/page.tsx`
  - `SelfCareScreen` を描画するエントリへ変更
- `src/features/self-care/components/*`
  - 表示を wellness + metrics のみに絞る
- `src/features/today/components/daily-condition-card.tsx`
  - 3段階UIを廃止し、5段階の身体/心入力に置換
- `src/features/today/use-today-data.ts`
  - `daily_wellness` を読み書きするよう変更
- `src/features/i18n/messages/{ja,en}.ts`
  - 「コンディション」命名へ文言更新

## データフロー

1. Today または コンディション画面で体調入力
2. `daily_wellness` に保存
3. コンディション画面で指標値入力
4. `daily_metrics` に保存
5. 履歴画面で wellness/metrics を読み出し、日別とグラフに反映

## エラーハンドリング

- 身長/体重/体脂肪率は未入力を許容
- 数値形式不正時は入力直下で明示エラー
- 保存失敗時は既存パターンに沿って失敗を可視化し、黙殺しない

## テスト観点

1. コンディション画面で wellness + metrics が保存できる
2. Today で更新した wellness がコンディション画面に反映される（逆方向も同様）
3. 保存済み metrics が履歴グラフに反映される
4. 既存の運動ログ導線（Today推薦・Library・History日別）が壊れない
