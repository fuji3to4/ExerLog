# ボタンの見た目の見直し（アプリ全体） 設計

日付: 2026-10-29
状態: 承認済み

## 背景と目的

動画まわりを YouTube 風に見直したあと、ユーザーから次の声があった。

- 「濃いべた塗りのボタンがダサく感じてるのかも」
- 「ボタンに対して文字が大きいヤツ」

特に気になると挙がった場所は次のとおり（ユーザーの言葉）。

- 「今日」の上の「＋ 記録する」「動画を選ぶ」
- 設定の「データ管理」以降
- ライブラリのセットを表示しているボタン
- 動画の編集モードのときのボタン全部
- 「など」

モックアップ（`.superpowers/brainstorm/3255-1793264881/content/button-styles.html`）で「今」と3案（A 淡い色、B 線だけ、C 文字だけ）を見比べ、ユーザーは **A** を選んだ。適用範囲は**アプリ全体**（ユーザーの判断）。

## ゴール：A 案のルール

ボタンの種類ごとに、次の見た目にそろえる。色の値はモックアップのものではなく、テーマ変数から作る。

| 種類 | 見た目 |
|---|---|
| 主ボタン（今の濃いべた塗り：`variant="default"`、`.today-screen__primary-button`、`.settings-action-button` の主、ダイアログの「保存」など） | 淡い主色の地（主色を薄くしたもの）＋主色の文字。影はなし |
| 副ボタン（今の `secondary`、`outline`、`--secondary` の類） | 塗りなし＋細い枠線＋通常の文字色 |
| 危険ボタン（削除など。`destructive`、`--danger`） | 淡い赤の地＋赤の文字。べた塗りの赤はやめる |
| 文字だけ・ゴースト（`ghost`、`link`） | 今のまま |
| 保存済みの表示（`.save-button--saved`、今は緑のべた塗り `#3aa76d`） | 淡い緑の地＋緑の文字（私の判断）。成功を表す新しいテーマ変数を全テーマに足す |
| 選択状態の切り替えボタン（セットの列、「今日」の切り替え、履歴の期間ボタンなど `aria-pressed` や選択中の表示を持つもの） | 選択中は淡い主色の地＋主色の文字＋薄い主色の枠。選択されていないものは塗りなし＋細い枠線 |

**大きさと文字**

- 高さは 36px 前後（`2.25rem`）にそろえる。
- 文字は 13px 前後（`0.8125rem`）、太さは中太（600 程度）。今の 48px・14px 太字はやめる。
- 横の余白は文字に合わせて詰める（14px 前後）。
- 丸いボタン（rounded-full）の形は今のままにする。
- 小さいボタン（`size="sm"`、セットの列など）は 32px 前後。
- アイコンだけのボタン（`size="icon"`）は 36px 角にする。
- 押せる範囲も見た目と同じ大きさにする（私の判断）。
  - 今は基本クラスの `min-h-12` で 48px の押せる範囲が確保されているが、それも外す。
  - 見えない広い押し範囲は作らない。36px・32px は WCAG 2.5.8 AA の目安（24px）を満たす。
  - 前回の作業の小さなボタン（36px）と同じ考え方にそろえる。

**使いやすさ**

- キーボードのフォーカスの表示（`focus-visible` のリング）は残し、見えるようにする。
- 押せない状態（disabled）は今と同じく薄くする。
- 「淡い地＋主色の文字」でも文字が読めること。明るい・暗い・別配色のどのテーマでも、地と文字の差が十分あること（WCAG AA の目安 4.5:1）。
  - 暗いテーマで淡い地が明るすぎて浮く場合は、そのテーマ用の値（暗めの主色の地）を用意する。

## 範囲

- **アプリ全体のボタン**が対象。共通の `Button`（`src/components/ui/button.tsx` の `buttonVariants`）と、`globals.css` のボタン用クラスを変える。
  - クラスの例：`.today-screen__primary-button`、`.settings-action-button*`、`.button-row .button-secondary`、`.set-switcher__button`、`.exercise-set-menu__button`、`.history-screen__preset-btn`、`.save-button--saved`、各ダイアログの actions など。
  - 画面ごとに Tailwind のクラスでべた塗りを直接書いているボタンがあれば、それも同じルールにそろえる。どこにあるかの洗い出しは作る人に任せる。
- ユーザーが特に挙げた場所は、必ず A 案になっていること。
  - 「今日」の「＋ 記録する」「動画を選ぶ」
  - 設定のデータ管理以降
  - ライブラリのセットの列
  - 編集モードのボタン（「＋ エクササイズを追加」「編集」「削除」）
- 前回の作業で作った「できた」「一部できた」の小さな枠線ボタンは、すでに A の副ボタンに近い。高さと文字の大きさだけ、上のルールにそろえる。

## ゴールではないこと

- **カレンダーの日付のマス。** 履歴のカレンダーの日付は「ボタン」ではなく表のマスとして扱い、今のまま残す（私の判断）。前後の月への移動ボタン（`.history-calendar__nav-btn`）は対象にする。
- **動画の再生ボタン**（サムネイル上の ▶）とサイドバーのナビゲーションは対象外。
- **入力欄・セレクト・スイッチ・チェックボックスなど、ボタン以外の部品。** 入力欄の高さは今のまま。ボタンと並ぶ行で高さがずれて見苦しい場合だけ、作る人の判断で合わせてよい。
- 配色そのもの（テーマの色）の変更。
- ボタンの文言や配置の変更。

## 失敗と言えること

- まだ濃いべた塗りのボタンが残っている。特にユーザーが挙げた場所に残っているのは失敗。
- 文字が地に溶けて読みにくい。特に暗いテーマや別配色で。
- 主ボタンと副ボタンの区別がつかなくなり、どれを押せばよいか分からない。
- フォーカスの表示が消える。

## 制約

- 色はテーマ変数（`globals.css` の `--primary`、`--accent-*`、`--destructive` など）から作る。新しい変数を足すのはよい。その場合は全テーマに定義する。
- `src/app/globals-theme.test.ts` は、テーマ変数の使い方をセレクタごとに固定している。新しいデザインに合わせて期待値を更新してよい。ただし「テーマ変数を使っている」ことを確かめる部分は残す。
- 既存の動き（押したときの処理、`aria-pressed`、disabled）は変えない。既存テストは、見た目のクラス名を直接見ているもの以外は変えずに通ること。

## 作る人に任せること

- 淡い地の作り方。例：`hsl(var(--primary) / 0.12)` のような透明度にするか、新しい変数にするか。
- 一括で変えるか、画面ごとに変えるかの進め方。
- ボタン用 CSS の整理。重複したクラスをまとめてよい。
- 見た目の確認。少なくとも「今日」・ライブラリ（編集モード含む）・設定・履歴・ダイアログ1つを、明るいテーマと暗いテーマで目視する。
