# 1日タイムライン・記録時刻・リアクション・BMI・日本語化 設計

日付: 2026-10-20
状態: 承認済み

## 背景と目的

利用者からのフィードバックに対応する。利用者は1日の中で **朝・動画の前・動画の後・夜** に体調を記録したい。しかし今は次の問題がある。

- 体調は1日1件で、2回目を保存すると上書きされる。
- 運動を「何時に」「何分何秒」やったかが残らない。
- 動画を見たこと自体が記録されない。
- 保存ボタンを押しても、記録されたかどうか分からない。

このため、1日の出来事（体調・動画視聴・運動）を**時刻付きで何件でも記録**し、**縦のタイムライン**で振り返れるようにする。あわせて次の要望にも対応する。

- BMIの自動計算
- カレンダーの花丸バッジ
- 英語のまま残っている画面文言の日本語化

成功の姿：「今日」の画面を開くと、朝・動画前・動画後・夜の体調と、視聴・運動が時刻順に並んで見える。何かを押すと、記録されたことがはっきり分かる。

## ゴール

1. 体調を1日に何回でも、時刻付きで記録できる。
2. 動画の視聴を時刻付きで記録できる。
3. 運動記録に、実施した時刻と長さ（秒単位）を残せる。
4. 「今日」の画面に縦のタイムラインを表示する。記録はあとから時刻・中身の修正や削除ができる。
5. 保存したことが目で見て分かるリアクションを付ける。
6. 体重記録時にBMIを表示し、グラフでもBMIを見られるようにする。
7. カレンダーで、運動した日に花丸、体調・視聴だけの日に小さな印を付ける。
8. 英語が残っている画面文言を日本語化する。

## ゴールではないもの

- 身長・体重・体脂肪率（body metrics）とセルフケアの「1日1件」の作りは変えない。
- BMIの判定（「肥満」など）は表示しない。数値のみ。
- 画面下に出るトースト通知は作らない（ユーザー判断：記録はあとから消せるので不要）。
- おすすめロジック（`wellness-to-condition.ts`）の考え方は変えない。入力元だけ新しい体調記録に合わせる。

## 避けたいこと（これが起きたら失敗）

- 新しい作りで記録した内容が、同期や再読み込みで消えたり元に戻ったりする。
- 押したのに何も起きないように見える操作が残る。
- 英語と日本語が混ざった画面が残る（言語設定が日本語のとき）。

## 現状（2026-10-20 時点のコード）

- 保存は IndexedDB（Dexie）で、`src/features/storage/app-db.ts` のスキーマが現在 v6。型は `src/lib/types.ts` にある。
- 体調：`DailyWellnessEntry` の主キーが `date` で、1日1件。入力箇所は次の2つ。
  - 今日画面 `src/features/today/components/daily-condition-card.tsx`
  - 体調画面 `src/features/self-care/components/wellness-card.tsx`
- 運動：`ExerciseLog` に一意制約 `&[date+exerciseId]` があり、1日1動画1件。`loggedAt` は記録時刻。
- 動画：`ExerciseVideo.durationMinutes` で、分単位。使われている箇所は次のとおり。
  - CSV（`public/exercises.csv`）
  - `scripts/csv-to-catalog.js`
  - `src/features/settings/csv/exercise-csv.ts`
  - `exercise-form-modal.tsx`
  - 各表示
- 視聴記録はない。
- カレンダー：`src/features/history/history-query.ts` の `listCompletedDaysInMonth` が運動ログだけを見ている。
- 同期：`src/features/sync/sync-config.ts` が各テーブルを Google スプレッドシートと同期する。CSV書き出しは `src/features/settings/csv/history-csv.ts`。
- 日本語化：独自の仕組みで、`src/features/i18n/messages/{ja,en}.ts` と `useTranslation()` を使う。

## 決まったこと（ユーザーの判断）

### 記録モデル

- 体調は1日に何回でも記録できる。各記録に時刻を付ける。項目は今と同じ（からだ1〜5、こころ1〜5、メモ）。朝・動画前後・夜で項目は変えない。
- 動画視聴を時刻付きで記録する。
- 運動記録には「何時にやったか」と「何分何秒やったか」の両方を残す。
- 動画の長さは秒単位で持つ。表示は詰めやすいように変えてよい（UIの変更も可）。

### 今日の画面：縦の時刻ライン（モックアップ案A）

- 左に時刻、右に記録カード。種類ごとに点の色を変える（体調・視聴・運動）。
- 上部に「＋ 体調を記録」ボタンと「動画を選ぶ」ボタンを置く。
- 記録にはラベル（朝／動画前／動画後／夜）を付ける。
- 運動の記録には長さを `5:30` の形で表示する。

### リアクション

- 保存系ボタンは、押すと1〜2秒間、緑の「✓ 保存しました」に変わる。
- タイムラインに追加された記録は、緑の枠とポップのアニメーションで現れる。
- 運動の「やった」を押したときは、大きな花丸 💮 と「おつかれさま！ ○分○秒 やりました」を一瞬表示する。対応する端末では軽く振動させる。
- 画面下のトースト通知は出さない。

### カレンダー

- 運動した日には花丸を付ける。
- 体調記録だけの日には小さな印を付ける。

### BMI

- 体重を記録したときに、その場でBMIを表示する。
- グラフでもBMIを見られるようにする。

### 日本語化

- グラフの選択肢を日本語化する。
- 履歴ページなど、英語が残っている所を日本語化する。

## 私（Claude）の判断で決めたこと

ユーザーが変更できる。

- **ラベルの自動判定**：保存せず、表示のたびに計算する。
  - 動画前：その日の視聴記録の直前（30分以内）の体調。
  - 動画後：視聴または運動記録の直後（30分以内）の体調。
  - 朝：上のどちらでもなく、時刻が4:00〜10:59の体調。
  - 夜：上のどちらでもなく、時刻が18:00以降の体調。
  - どれにも当たらなければラベルなし。
- **時刻の入力**：記録時は押した時点の時刻が自動で入る。編集画面で時刻（時:分）を直せる。日付をまたぐ移動はしない。
- **長さの初期値**：動画の長さ（秒）を初期値にして、編集で直せる。入力UIは「分」「秒」の2つの数値欄。
- **運動ログの重複**：`&[date+exerciseId]` の一意制約を外す。同じ動画を1日に2回やれば2件になる。
- **視聴の記録タイミング**：動画詳細画面で再生または外部リンクを開いた時点で、視聴記録を1件作る。同じ動画を10分以内に続けて再生した場合は作らず、重複を避ける。
  - YouTube iframe は再生開始を検知しにくい。そのため「プレーヤー領域をタップした／リンクを開いた」で代用してよい。実装時に可能な方法を選ぶこと。
- **既存データ**：「データのリセット」節のとおり、移行は不要。
- **動画の長さ**：`durationMinutes` を廃止して `durationSeconds` にする。
  - `public/exercises.csv`、取り込みCSV、ライブラリ編集フォームのすべてを秒に統一する。
  - 旧 `durationMinutes` 列の後方互換は持たない（リセット可のため）。
- **おすすめ運動の入力**：その日の最新の体調記録をもとにする。記録がまだなければ今と同じ初期値を使う。入力欄の未保存の値では変えない。
- **「やった」「一部できた」ボタン**：
  - 押すたびに運動記録を1件追加する。トグルや取り消しの動きはやめる。取り消しはタイムラインの削除で行う。
  - カードには「今日2回」のように回数を出す。
  - 「一部できた」は残す。長さの初期値はどちらも動画の長さで、あとから直せる。
  - 花丸の演出は両方で出す。「一部できた」のときの文言は「おつかれさま！」だけにする。
- **過去の日への追加**：履歴の日別表示からも記録を追加できる。日付はその日に固定する。時刻の初期値は今の時刻で、直せる。
- **花丸の対象**：動画を見ただけで運動していない日は、小さな印にする。
- **BMI**：
  - 計算式は `体重kg ÷ (身長m)²` で、小数1桁に丸める。
  - 身長は、その日以前に記録した最新の値を使う。
  - 身長がなければ「身長を記録するとBMIが出ます」と表示する。
  - BMIは保存せず、グラフ用にも都度計算する。
  - 判定（肥満度など）は出さない。
- **履歴の日別表示**：履歴でカレンダーの日を選んだときの表示（`day-summary.tsx`）も、同じタイムライン表示にそろえる。
- **体調画面（/self-care）の体調入力**：今日の画面と同じく「新しく1件追加」の動きにする。
- **グラフの体調**：1日に複数件ある場合は、その日の平均を1点として描く。

## 日本語化の対象（確認済みの箇所）

- `history-graphs.tsx` の `METRIC_OPTIONS` → 体重／体脂肪率／身長／BMI／からだの調子／こころの調子
- 期間ボタン `7d/30d/90d/all` → 7日／30日／90日／全期間
- `history-graphs.tsx` の `Loading...` → 読み込み中…
- `history-graph-query.ts` のラベルと単位（`METRIC_LABELS`、wellness ラベル、`SELF_CARE_UNITS` の count/minutes/done）
- `ja.ts` の `history_mode_summary` と `history_mode_graphs` → まとめ／グラフ
- `history_graph_metric_label: "メトリック"` → 「表示する項目」など自然な言い方にする
- `app-sidebar.tsx` の nav ラベル（`messages.nav_*` を使う）と「Navigation」見出し
- 上記以外にも、ハードコードされた英語のUI文言が見つかれば、すべて `messages` 経由にして日本語訳を付ける。英語モードの表示は保つ。

## データのリセット（ユーザー判断）

まだベータ版なので、以前のデータとの整合性は保たなくてよい。

- IndexedDB は新しいスキーマで作り直してよい。古いバージョンからの移行処理は書かず、既存データは消えてよい。
- Google スプレッドシートも、新しいタブ構成で作り直してよい。旧タブを読み込む互換も不要。
- ただし作り直したあとに、古いデータが原因でエラーになったり変な表示になったりしないこと。例えば、旧タブが残ったシートに同期しても壊れないこと。

## 影響する周辺機能

- **Google 同期**（`sync-config.ts`、`sync-engine.ts`）：
  - 新しいテーブルと新しい列（時刻・長さ・視聴）をシートに追加する。
  - **タイムラインでの修正・削除をスプレッドシートにも反映させる（ユーザー判断）。** 今の同期は、未登録のキーを追記するだけで、更新・削除をしない。さらに手動同期（full）では、シートの内容でローカルを置き換える。このため、修正・削除した記録が同期で元に戻ってしまう。これを直す。
    - 更新は、行を上書きするか、タブ全体を書き直す。
    - 削除は、削除の印を持つか、タブ全体を書き直す。
    - どちらの方式を使うかは builder に任せる。
  - 受け入れ条件：記録を修正・削除してから「今すぐ同期」をしても、その修正・削除が保たれ、シート側にも反映されている。
- **CSV 書き出し**（`history-csv.ts`）：体調は複数件、運動には長さ、視聴記録を含めて書き出す。
- **データ削除**（設定画面）：新しいテーブルも消す対象に入れる。

## builder に任せること

- Dexie スキーマの具体的なテーブル設計（作り直し可）。
- 同期で更新・削除をどう反映させるかの方式。
- 体調画面と今日画面の重複ロジックの整理方法。
- リアクションのアニメーションの具体的な実装（CSS か小さなライブラリか）。新しい依存は最小限にする。
- 色や間隔などの細かな見た目。既存のデザイン（shadcn/Tailwind、`#31507d` 系）に合わせる。
- テストの粒度。既存の Vitest と fake-indexeddb のテストを壊さず（スキーマ変更に合わせた書き換えは可）、同期の更新・削除とBMI計算とラベル判定にはテストを付ける。
