# セルフケア・着用・症状を記録モジュールとして追加する 設計

日付: 2026-10-28
状態: 承認済み

## 背景と目的

リンパ浮腫患者ネットワークの代表から、次の記録項目を追加してほしいという要望があった。

- **セルフケアの記録**：スキンケア、弾性着衣、弾性包帯、運動、体重管理、その他
- **浮腫の状態・症状の記録**：むくみ、痛み、重だるさ、疲れやすさ、関節が曲げにくい、指で押すとあとが残る（圧痕）、皮膚の変化、蜂窩織炎、症状なし

使い方は2つあると考えている（ユーザーの判断）。

1. 受診の日に、主治医や看護師に見せる。たとえば「弾性着衣は毎日平均◯時間着けていた」「痛みは週に2回くらい、左腕に出た」と言えるようにする。
2. 毎日、その日のケアと体の状態を振り返る。

これは、記録モジュールの土台（`docs/superpowers/specs/2026-10-27-record-modules-foundation-design.md`）で「段階3」としていたもののうち、**セルフケア**と**蜂窩織炎**にあたる。

使いやすいかどうかは、実際に使ってもらうまでわからない（ユーザーの言葉）。そのため、今の土台の決まり（タイムラインに出る、設定で ON/OFF できるモジュール）に沿ってまず作り、使ってもらってから直していく。作り込みすぎないことを優先する。

## ゴール

1. 新しいモジュールを3つ追加する。
   - **セルフケア**（id: `selfcare`）：スキンケア、運動、その他
   - **着用**（id: `compression`）：弾性着衣、弾性包帯
   - **症状**（id: `symptoms`）

   どれも土台のモジュールの決まりに従う。入力フォーム、タイムラインのカード、履歴の見返し画面、期間のまとめのカード、同期、CSV 書き出しをそれぞれ持ち、設定から ON/OFF と並べ替えができる。
2. 着用はセルフケアから独立したモジュールにし、単独で ON/OFF できるようにする（ユーザーの判断）。弾性着衣と弾性包帯は、1つのモジュールの中で選ぶ（ユーザーの判断。分けるかどうかは使ってもらってから考える）。
3. セルフケアでは、項目ごとに「やった」を記録できる。着用では、**着けた時刻と外した時刻**を記録できる。
4. 入力の手順は、ほかのモジュールと同じにする（ユーザーの判断）。「＋記録する」からモジュールを選ぶとフォームが開き、今の時刻が入った状態で保存する。今日の画面に専用のボタンは置かない。
5. 症状では、症状ごとに**強さ（3段階）**と**場所**を記録できる（ユーザーの判断）。「症状なし」はフォームを開いて1回のタップで記録できる。
6. 蜂窩織炎は症状の1つとして記録する。以前の設計で独立したモジュールとして予定していた「蜂窩織炎（入院・通院・無治療）」は、この症状モジュールに含める（ユーザーの判断）。
7. 受診用の期間のまとめに、3つのモジュールのカードを出す。

## ゴールではないもの

- **体重管理**の項目。体重は今の身体モジュールで記録する（ユーザーの判断）。セルフケアの一覧には入れない。
- セルフケアの項目を利用者が追加・編集・削除すること。項目は固定とし、足りないものは「その他」とメモで残す。
- 症状と写真を結び付けること（皮膚の変化の写真など）。写真は写真モジュールで別に撮る。
- 着け忘れ、外し忘れ、記録忘れを知らせること。通知も、画面上の注意書きも出さない。
- 今日の画面に、着用のワンタップのボタンを置くこと。ほかのモジュールと同じ「＋記録する」から入力する（ユーザーの判断）。
- 弾性着衣の購入履歴と受診メモ。どちらも段階3の別のモジュールとして、改めて設計する。
- 古いセルフケアのデータ（`selfCareCatalog`、`dailySelfCareLogs`、シートの `DailySelfCare` タブ）を生かすこと。下記「古いセルフケアのデータ」を参照。

## 避けたいこと

- 記録を促したり、記録していないことを責めたりする作り。記録するかしないかは利用者次第で、ゆるく使えることを大事にする（ユーザーの判断）。

## セルフケアモジュール

### 項目と記録の形

| 項目 | 記録の形 |
| --- | --- |
| スキンケア | やった（チェック）＋メモ |
| 運動 | やった（チェック）＋分数（任意）＋メモ |
| その他 | やった（チェック）＋メモ（何をしたかを書く） |

- 運動は、アプリの運動・動画の記録とは別のものとする。アプリの外でした運動（散歩、水中ウォーキングなど）も残せるようにするため（ユーザーの判断）。
- 1件の記録は1つの項目を持つ。1日に何回記録してもよい。それぞれが日時を持ち、タイムラインに出る（私の判断。土台では、すべての記録が日時を持つため）。

### 入力フォーム

- 「＋記録する」から「セルフケア」を選ぶと、フォームが開く。項目を選び、日時（初期値は今）、運動なら分数、メモを入れて保存する。
- 後から入力する場合（夜にまとめて入れるなど）も、このフォームで日時を変えて入れる。
- 編集は、タイムラインのカードをタップして開く（土台のとおり）。

### タイムラインのカード

- 「スキンケア」「運動 30分」「その他：リンパドレナージ」のように出す。メモがあれば下に出す。

### 履歴の見返し画面

- 期間の切り替え（土台の部品）を使い、項目ごとに「やった日数」を出す。運動は合計の分数も出す。
- 細かい見せ方は builder に任せる。

### 期間のまとめのカード

- 項目ごとに、期間内でやった日数を「◯日／期間の日数」の形で出す。
- 運動は、合計の分数も出す（分数が入っている記録だけを足す）。
- 記録がない項目は出さない。

## 着用モジュール（弾性着衣・弾性包帯）

### 記録の形

- 1回の着用を1件の記録とする。記録は「種類（弾性着衣・弾性包帯）」「着けた時刻」「外した時刻」「メモ」を持つ。外した時刻は、まだ外していない間は空にする。
- 記録の日時（`recordedAt`）は着けた時刻とする。日付も着けた時刻で決まる。夜に着けて翌朝外した場合も、着けた日の記録になる（私の判断）。
- 着用時間は「外した時刻 − 着けた時刻」で求める。保存はしない。
- 同じ種類（弾性着衣、または弾性包帯）で、外していない記録は同時に1件までとする（私の判断）。弾性着衣と弾性包帯は、同時に着用中でもよい。
- ただし、この決まりは端末ごとにしか守れない。2台の端末で同期すると、同じ種類の外していない記録が2件になることがある。そのときは、フォームは着けた時刻が新しいほうを「外す」対象にする。もう1件はタイムラインから直す（私の判断）。
- 着用時間は、着けた日の分として数える。期間のまとめの端でも同じとする（私の判断）。

### 入力フォーム

- 「＋記録する」から「着用」を選ぶと、フォームが開く。手順はほかのモジュールと同じで、開く→保存の2〜3タップになる（ユーザーの判断）。
- フォームでは、まず種類（弾性着衣・弾性包帯）を選ぶ。初期値は弾性着衣とする（私の判断）。
- 選んだ種類に**着用中の記録がないとき**は、新しい着用の記録として開く。着けた時刻に今の時刻が入り、外した時刻は空のまま保存できる。
- 選んだ種類に**着用中の記録があるとき**は、その記録を「外す」形で開く。「弾性着衣 8:10〜 着用中」と見せ、外した時刻に今の時刻を入れておく。保存すると、その記録が閉じる（私の判断）。
  - この形のときも、「新しく着けた記録にする」に切り替えられるようにする。外した時刻を入れ忘れたまま次の日に着けた場合のため。
- 後から入力する場合（夜にまとめて入れるなど）は、着けた時刻と外した時刻の両方を入れて保存する。
- 編集は、タイムラインのカードをタップして開く（土台のとおり）。
- 見た目と、2つの形の切り替え方は builder に任せる。

### 外し忘れ

- 外し忘れを知らせる表示や通知は出さない（ユーザーの判断）。記録するかしないかは利用者次第という、ゆるい使い方を大事にする。知らせがうるさくてアプリを使わなくなるほうが困る。
- 外した時刻が空の記録は、フォームで外すか、タイムラインのカードから直すまで「着用中」のままにする。
- 自動で外したことにはしない。

### タイムラインのカード

- 着けた時刻の位置に「弾性着衣 8:10〜21:30（13時間20分）」と出す。着用中なら「弾性着衣 8:10〜 着用中」と出す。メモがあれば下に出す。
- 外した時刻の位置に、別の行を出すかどうかは builder に任せる。出さなくてもよい。

### 履歴の見返し画面

- 期間の切り替えを使い、種類ごとに日ごとの着用時間を棒グラフで出す。1日に複数回着けた日は合計する（私の判断）。
- 細かい見せ方は builder に任せる。

### 期間のまとめのカード

- 種類ごとに、着用した日数（「◯日／期間の日数」）と、1日あたりの平均の着用時間を出す。平均は、着用した日だけで割る（私の判断）。外した時刻が空の記録は、時間の計算から除く。
- 記録がない種類は出さない。

## 症状モジュール

### 項目と記録の形

1件の記録は「その時点での状態」を表す。1件の中に、あった症状を複数入れられる。1日に何回記録してもよい。

| 症状 | 強さ | 場所 | そのほか |
| --- | --- | --- | --- |
| むくみ | ○ | ○ | |
| 痛み | ○ | ○ | |
| 重だるさ | ○ | ○ | |
| 疲れやすさ | ○ | | |
| 関節が曲げにくい | ○ | ○ | |
| 指で押すとあとが残る（圧痕） | ○ | ○ | |
| 皮膚の変化 | ○ | ○ | |
| 蜂窩織炎 | | ○ | 入院・通院・治療なし |

- **強さ**は「軽い・中くらい・強い」の3段階（ユーザーの判断で3段階。言葉は私の案）。選ばなくても保存できる。
- **場所**は「右腕・左腕・右脚・左脚・その他」から複数選べる（私の案。周径の記録と同じ分け方）。「その他」（体幹、陰部、顔など）は、記録のメモに書く。選ばなくても保存できる。
- 疲れやすさは体全体のことなので、場所を持たない（私の判断）。
- **蜂窩織炎**は、強さの代わりに「入院・通院・治療なし」を選ぶ。以前の設計で独立したモジュールとしていた内容を、ここに含める（ユーザーの判断）。
- 記録全体に、メモを1つ付けられる。
- **症状なし**は、症状を1つも持たない記録とする。フォームの「症状なし」を押すと、すぐに今の時刻で保存する（私の判断）。症状を選んでいる途中に「症状なし」は押せない。

### 入力フォーム

- 症状の一覧を並べる。症状を押すと「あった」になり、その下に強さと場所の選択が出る。
- 入力の手間を減らすため、強さと場所は選ばなくても保存できる。
- 細かい見た目は builder に任せる。一覧が長いので、スマートフォンの画面で全体を見渡しやすいことを優先する。

### タイムラインのカード

- 「むくみ（中・左腕）、痛み（軽・左腕）」のように、あった症状を並べる。蜂窩織炎は「蜂窩織炎（通院・右脚）」と出す。
- 症状なしの記録は「症状なし」と出す。
- メモがあれば下に出す。

### 履歴の見返し画面

- 期間の切り替えを使い、症状ごとに「あった日数」と「一番強かった強さ」を出す。
- 日ごとの様子がわかる表示（症状ごとに、あった日に強さの印を付けるカレンダー状の表など）があるとよい。形は builder に任せる。
- 蜂窩織炎は、記録の一覧（日付、入院・通院・治療なし、場所）も出す。発作ごとにまとめず、記録を日付順に並べる（ユーザーの判断）。

### 期間のまとめのカード

- 記録した日数と、そのうち「症状なし」だけの日数。
- 症状ごとに、あった日数、一番強かった強さ、出た場所。
- 蜂窩織炎があった日数と、入院・通院・治療なしの内訳（日数）。発作の始まりと終わりは記録しないので、発作の回数は出さない（ユーザーの判断）。
- 期間内に一度も出なかった症状は出さない。

## データと同期

- 3つのモジュールは、それぞれ自分のテーブルとシートのタブを持つ（土台の決まりのとおり）。テーブルの形、タブの名前、列の並びは builder に任せる。
- 症状の記録は、1件の中に複数の症状を持つ。シートと CSV では、1行に1件の記録を出し、症状ごとに列を分ける（例：「むくみ_強さ」「むくみ_場所」）と、表計算ソフトで集計しやすい（私の案）。最終的な形は builder に任せる。
- 項目と症状の識別子は英語の固定の文字列にする（`skincare`、`compression_garment`、`edema`、`cellulitis` など）。画面の表示名は i18n の仕組みで日本語と英語を出す。

### 古いセルフケアのデータ

- `selfCareCatalog`（ストレッチ・散歩・入浴・瞑想）、`dailySelfCareLogs`、シートの `DailySelfCare` タブは、画面がないまま残っている仮のものである。項目も記録の形（1日1項目1件で、日時が意味を持たない）も、今回のものと合わない。
- 新しいセルフケアモジュールと着用モジュールは、これを使わず新しいテーブルを作る（私の判断）。
- 古いテーブルと同期の設定は削除する。スプレッドシートの古い `DailySelfCare` タブと `SelfCareCatalog` タブは、読みも書きもせず、消しもしない（土台で `Measurements` タブを扱ったときと同じ）。
- 画面がなかったので、利用者が記録したデータはないと見込んでいる。

## builder に任せること

- テーブルの形、Dexie のバージョン上げ、シートのタブ名と列。
- フォーム、タイムラインのカード、見返し画面、まとめのカードの細かい見た目。
- アイコンと、タイムラインの点の色。
- 着用時間の表記（「13時間20分」「13.3時間」など）。
