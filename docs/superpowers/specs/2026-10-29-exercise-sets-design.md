# マイリスト（セット） 設計

日付: 2026-10-29
状態: 承認済み

## 背景と目的

ライブラリに動画が増えると、「いつもやる動画」がどれだったか分からなくなる（ユーザーの言葉）。そこで、動画の「マイリスト」を作れるようにする。ユーザーのイメージは「いつもやるセット」で、「朝用」「むくみの日」のように、いくつでも作り分けられるようにしたい。

使い方は、セットの中からその日の気分で何本か選んでやる形（ユーザーの言葉）。上から順番に全部こなすプレイリストではない。

画面上の呼び名は「セット」にする（私の判断。モックアップでもこの呼び名を使い、ユーザーから異論はなかった）。コード上の名前は `ExerciseSet` を想定している。

## ゴール

### ライブラリでの管理

- **カードのメニュー（⋯）からセットに出し入れする**（ユーザーの判断）。
  - メニューは、カードに付けて開くドロップダウンにする。下から出るシートにはしない（メモリにある方針）。見本は `src/features/modules/components/add-record-menu.tsx`（Radix DropdownMenu、`modal={false}`）。
  - メニューには全部のセットをチェックボックス付きで並べ、付け外しで出し入れする。メニューは閉じずに、続けて複数のセットを操作できる（私の判断）。
  - 1本の動画を複数のセットに入れられる。
  - いちばん下に「＋ 新しいセットを作る」を置く。名前を入れると、そのセットが作られ、その動画も入る（私の判断）。名前の入力方法（メニュー内の入力欄か、小さなダイアログか）は作る人に任せる。ただし、下から出るシートは使わない。
  - このメニューは編集モードでなくても使える（私の判断）。編集モードの「編集」「削除」ボタンは今のまま残す。
- **フィルターでセットを選ぶと、そのセットの動画だけを表示する**（ユーザーの判断）。
  - `library-filters.tsx` に「セット」の選択欄を足す。初期値は「すべて」。部位・目的・強度・長さ・並べ替え・検索と組み合わせられる。
  - セットを選んでいるあいだだけ、選択欄の横に「⋯」を出す。中身は「名前を変える」「このセットを消す」（私の判断）。
  - セットを消すときは確認を1回出す。消えるのはセットだけで、動画は残る。
  - セットを選んでいるときは「朝用：4本」のように本数を出す（私の判断）。
- **セットの中の並び順は、追加した順にする。** 並べ替え機能は作らない（私の判断。気分で選ぶ使い方なので不要と考えた）。ライブラリでセットを選び、並べ替えが既定のときもこの順で出す。
- ライブラリから動画が消えると、その動画はどのセットにも表示されなくなる。中身が空になったセットも残る。
  - やり方は「セットのデータは書き換えず、読むときにライブラリにない id を飛ばす」にする（私の判断）。
  - 動画が消える経路は4つある（カードの削除、ライブラリ全削除、CSV 読み込みによる置き換え、別の端末での削除の同期）。この方法なら、どの経路でも同じように動き、同期による余計な書き込みも増えない。
  - 本数の表示や「今日」の一覧も、ライブラリにある動画だけを数える。
  - 副作用：同じ id の動画を CSV で読み込み直すと、元のセットに戻ってくる。これは困らない（むしろ便利な）動きとして受け入れる。
- 「すべての記録を消す」（`clear-all-records.ts`）はライブラリ（`exercises`）を消さないので、セットも消さない。

### 「今日」での切り替え

- **「今日のおすすめ」の見出しの下に、ボタンを横一列に並べて切り替える**（ユーザーが選んだA案）。
  - 先頭は「今日のおすすめ」。続けて、作った順に全部のセットを並べる。
  - 選んでいるものを強調する。数が多いときは横にスクロールする。
- 見出しは選んでいるものの名前にする（「今日のおすすめ」または「朝用」など）。
- セットを選ぶと、そのセットの動画を**全部**、追加した順に並べる。おすすめのように3本に絞ったりはしない。
- 各カードは今のおすすめカード（`RecommendedExerciseCard`）と同じ。「見る」「記録」と今日の回数を出し、役割ラベル（いつもの・はじめて など）は出さない。
- セットを表示しているときは「別の3本にする」ボタンを出さない。説明文はセット用のもの（例：「今日の気分で選んでどうぞ」）に替える。文言は作る人に任せる。
- **次にアプリを開いたときは、前回選んだものから始まる**（ユーザーの判断）。
  - 覚えておくのは端末ごとで、localStorage に入れる（私の判断。`reshuffle-store.ts` と同じやり方）。
  - 覚えていたセットが消えていたら、「今日のおすすめ」に戻す。
- セットが1つもないときは、ボタンの列を出さず、今の画面のままにする（私の判断）。
- 空のセットを選んだときは、「ライブラリのカードの⋯から動画を追加できます」という一言とライブラリへのリンクを出す（私の判断）。
- 「他のエクササイズも見てみませんか？」のカードは今のまま残す。

### データと同期

- セットは IndexedDB（Dexie）に新しいテーブルとして保存し、Google スプレッドシートに同期する。そうすれば、スマホとPCでセットの中身が同じになる。
- 足し方は、これまでのテーブルと同じ手順で行う。
  - `src/lib/types.ts` に型を足す。
  - `app-db.ts` で v15 にする。
  - リポジトリでは、書き込みのたびに `updatedAt` を付け、削除時はトゥームストーンを残し、`scheduleSync()` を呼ぶ。
  - `sync-config.ts` の `tableSyncConfigs()` と `syncedDbTables()` に登録する。
- データの形は、1セット＝1レコードを想定している（私の判断）。
  - 中身は `{ id, name, exerciseIds: string[], createdAt, updatedAt }`。
  - スプレッドシートでは `exerciseIds` を JSON 文字列の1列にする。
  - 弱点：同期は最後に書いたほうが勝つので、2台で同時に同じセットを編集すると片方の変更が消える。1人で使うアプリなので、この弱点は受け入れる。
  - もっと良い形があれば、作る人が変えてよい。
- セットの CSV 書き出し・読み込みは作らない。
- ja と en の両方に文言を足す（`messages/ja.ts`、`messages/en.ts`）。
- リンパ浮腫向けの機能ではないので、モジュールタグは付けない。どのビルドでも使える。

## ゴールではないこと

- セットの中の並べ替え。
- セットを上から順に再生する、連続して自動再生する。
- やっていない動画への印、残りの本数のお知らせ、やり忘れの警告（ユーザーの方針「せかさない」）。
- 前回選んだセットを端末間で同期すること。
- アプリ全体の見た目の見直し。ユーザーの希望はあるが、マイリストの後に別のプロジェクトとして相談する。

## 失敗と言えること

- セットを入れたせいで、おすすめ（3本・役割・日ごとに固定・入れ替え）の動きが変わること。
- 動画をセットに入れるのに編集モードや別画面が必要で、手間が増えること。
- 下から出てくるシートが使われていること。

## 作る人に任せること

- 新しいセットの名前を入れる方法（シート以外）。
- コンポーネントやファイルの分け方、テストの細かい中身。
- 細かい文言と CSS。既存のクラスと見た目に合わせる。
- テストは既存のやり方（Vitest、`*.test.tsx` をそばに置く）で、リポジトリ、同期設定、ライブラリのメニューとフィルター、「今日」の切り替えと前回の選択の復元を確認する。
