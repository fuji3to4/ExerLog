# Design: 履歴画面の閲覧/編集モード切替と過去データ編集

**Date:** 2026-05-26  
**Status:** Approved

## 背景と課題

- 履歴日別サマリーでは現在、運動ログと体調（condition）の編集/削除が常時表示されている
- wellness（フィジカル/メンタル）とmetrics（身長/体重/体脂肪率）は表示のみで、履歴から編集できない
- ユーザー要望として、過去日付を含めて履歴から一元的に編集・削除したい

## 目標

1. 履歴画面に閲覧モード/編集モードのスイッチを追加する
2. 初期表示は閲覧モードにし、編集/削除UIを非表示にする
3. 編集モードで、以下を履歴から編集・削除できるようにする
   - 運動ログ（現仕様同等: 編集・削除）
   - 身長/体重/体脂肪率（編集・個別削除）
   - フィジカル/メンタル（編集・まとめ削除）
   - 体調（condition）（編集・削除）
4. データ未登録日の場合でも、編集モードで新規追加できるようにする（metrics / wellness）

## 非目標（今回やらないこと）

- 履歴画面での運動ログ「新規追加」導線の追加
- 履歴グラフUIの機能拡張
- Self Care実施ログの編集機能追加

## 変更方針

### 1) モード切替UI

- `DaySummary` 上部に「閲覧/編集」スイッチを追加
- モードは `DaySummary` 内部stateで管理し、初期値は閲覧モード
- 閲覧モードでは、全セクションの編集/削除アクションを非表示にする

### 2) セクション別挙動

- 運動ログ:
  - 編集モード時のみ既存の編集/削除ボタンを表示
  - 既存の編集モーダル・削除処理を再利用
- metrics（身長/体重/体脂肪率）:
  - 編集モード時、各項目に編集・削除ボタンを表示
  - 未登録項目にはその場で数値を入れられる追加フォームを表示
  - 削除は項目単位で個別実行
- wellness（フィジカル/メンタル）:
  - 編集モード時、編集ボタンと削除ボタンを表示
  - 未登録日は追加フォームを表示
  - 削除はフィジカル/メンタルのレコード単位でまとめて実行
- condition:
  - 編集モード時のみ既存の編集/削除ボタンを表示
  - 既存モーダル・削除処理を再利用

### 3) データ更新の責務

- 既存リポジトリを優先的に再利用し、必要最小限のAPIを追加する
- `daily-metrics.repository.ts` に単一metricの追加/更新/削除を扱う関数を追加
- `daily-wellness.repository.ts` に `deleteDailyWellness(date)` を追加
- 保存/削除完了後は `onChanged()` で日別サマリーを再取得し、画面整合を維持する

## データフロー

1. ユーザーが履歴で日付を選択
2. 日別サマリー表示時は閲覧モードでレンダリング
3. 編集モードONで、各セクションの編集/削除/追加UIを表示
4. 保存/削除操作で対応リポジトリを更新
5. `onChanged()` で当日サマリーを再取得し、最新状態を反映

## エラーハンドリング

- 保存/削除の失敗は握りつぶさず、既存実装方針に沿ってエラーを表面化する
- metrics入力は数値型を維持し、不正値を保存しない
- 削除確認は既存の確認ダイアログパターンを踏襲する

## テスト観点

1. 初期表示が閲覧モードで、編集/削除UIが表示されない
2. 編集モード切替で、運動・metrics・wellness・conditionの編集UIが表示される
3. metricsの追加/編集/個別削除が日付単位で正しく反映される
4. wellnessの追加/編集/まとめ削除が正しく反映される
5. conditionと運動ログの既存編集導線が編集モード時のみ有効である
6. 過去日付を選択した場合も同じ挙動で編集できる
