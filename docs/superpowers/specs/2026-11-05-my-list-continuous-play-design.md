# マイリストの連続再生・ループ・自動チェック 設計

日付: 2026-11-05

## 意図と背景

マイリスト（`ExerciseSet`）の動画を順番にこなすとき、今は動画ごとに詳細画面を開いて ▶ を押す必要があり、面倒。
運動中はスマホを床や机に置いて少し離れたところから見ているので、1 本ごとに手を伸ばして操作したくない。

一度 ▶ を押せばマイリストを最後まで（必要ならくり返し）流し続け、記録もできれば自動で付く、という状態にしたい。

## ゴール

- 今日の画面でマイリストを選んでいるとき、「▶ 連続再生」で中の動画を順番に自動再生する。
- **ループ**: オンなら最後の動画のあと 1 本目に戻って続ける。オフなら最後で止まる。
- **前／次**: 再生中に 1 本戻る・1 本飛ばす。
- **自動チェック**: オンなら、最後まで再生された動画に記録（`result: "did"`）を 1 件付ける。ループで 2 周すれば 2 件付く。

## 非ゴール

- 1 本の動画のくり返し（既存の start/end 区間ループはそのまま残す。ここでは触らない）。
- ライブラリ画面のマイリストからの連続再生（ライブラリは整理・編集の場所のまま）。
- 「おすすめ」（マイリスト未選択時のリスト）の連続再生。
- 「一部できた（partial）」の自動判定。閾値の決め方で複雑になるので扱わない。
- 全画面プレイヤー、画面の左右タップ操作（案 B は採用しなかった）。

## アンチゴール（動いても失敗とみなすもの）

- 自動チェックがオフなのに記録が付く。途中で飛ばした・止めた動画に記録が付く。
- 記録漏れを注意したり、再生を促したりする通知や警告を出す（ユーザー方針: 記録はゆるく）。
- 連続再生のために別画面へ移動させられる（ユーザーは「画面を移らない」案 C を選んだ）。
- 下から出てくるシート型のメニュー（ユーザー方針: メニューはその場に出るドロップダウン）。

## 決まっている振る舞い（ユーザーと合意済み）

画面は **案 C「今日の画面のマイリストの中で再生」**。

- **始め方**: 今日の画面でマイリストを選ぶと、リストの上に「▶ 連続再生」ボタンと、🔁 ループ・✓ 自動チェックの切り替えが出る。
- **再生中**: 画面は移らない。今流れている動画のカードだけがリストの中で大きく広がり、その場で埋め込み再生される。終わると次の動画のカードが広がって自動で再生が始まる。
- **前／次**: 再生中のカードのすぐ下に ⏮ ⏭。アプリのほかのボタンと同じ、色の薄い丸いボタン（`ui-style-preferences`: 36px 前後の薄い色のボタン、濃いベタ塗りは使わない）。
- **止める**: 再生が始まると「▶ 連続再生」ボタンが「■ 停止」に変わる。停止したら元のリスト表示に戻り、記録は付かない（**私の判断**）。YouTube プレイヤー自体の一時停止は「停止」ではなく、そのまま待つ。
- **カードのタップ**:
  - 連続再生していないとき → 今までどおり、その動画の詳細画面へ移る（既存のリンクは変えない）。
  - 連続再生中にほかのカードをタップ → 詳細画面へは移らず、その動画に飛んで続きを再生する。飛ばした分の動画には記録を付けない。
- **リストの ✓**: 新しい印は作らない。今ある「今日の記録回数」の表示が増えることで表す。手動で記録したときも同じに見える（**私の判断**）。
- **ループ・自動チェックの設定**: 前回の設定を覚えておく（この端末の中だけ。`selected-set-store.ts` と同じく localStorage 方式）。
- **自動チェック**: 最後まで再生された動画にだけ、その場で記録を付ける（カードの今日の回数が増える）。⏭ で飛ばした動画や途中で止めた動画には付けない。
- 自動チェックがオフのときの記録は、今までどおり手動。

## 制約・既存の前提

- 再生は YouTube の埋め込み（`src/lib/video/youtube.ts` の `getYouTubeEmbedUrl`）。動画の終わりを知るには YouTube IFrame Player API（`onStateChange` の `ENDED`）が必要。今は素の `<iframe src=…autoplay=1>` だけ。
- start/end 付きの動画は、今の埋め込みでは `loop=1&playlist=<id>` で区間をくり返す設定になっていて、そのままでは「終わり」が来ない。連続再生のときは区間ループを付けずに、end に達したら「終わった」と扱う。
- 記録は `useTodayData(date).logExercise(exercise, result)` から付ける（今日の画面の手動記録と同じ経路）。表示中の日付（`date`）に付く。
- 再生を始めたときの「見た」記録（`watchEvents`）は、詳細画面の `handleWatch` と同じく、各動画の再生が始まるたびに 1 件付ける。
- 文言はすべて i18n（`src/features/i18n/messages/*.ts`）に追加する。日本語と英語の両方。
- モバイルブラウザは、ユーザーが操作していないと自動再生を止めることがある。最初の ▶ はユーザーのタップなので問題ないが、2 本目以降は同じ埋め込みプレイヤーを使い回し、`loadVideoById` で中身を差し替えて続けて流すこと（iframe を作り直すと自動再生が止められることがある）。

## 作る人の判断に任せる部分

- IFrame API の読み込み方（スクリプトを一度だけ読み込む小さなフックなど）と、プレイヤーの状態をどのモジュールに持たせるか。
- 再生中カードの細かい見た目。今の `RecommendedExerciseCard` の大きさとの切り替え方。
- 埋め込めない動画（YouTube 以外の URL）: 連続再生では飛ばして次へ進む（**私の判断**）。全部が埋め込めない場合は「▶ 連続再生」を出さない。
- ループがオフで最後まで流れたら、プレイヤーを閉じて元のリスト表示に戻す（**私の判断**）。
- 自動チェックで記録を付けたときのお祝い表示（`celebrate`）: 出すなら控えめにして、動画を隠したり再生を止めたりしないこと（**私の判断**）。
- 自動記録の保存に失敗したとき: 手動記録と同じエラー表示（`log_save_error`）をそのカードに出し、再生は止めずに続ける（**私の判断**）。
- 再生中にマイリストを切り替えたり、画面を離れたりしたら連続再生は終わる（**私の判断**）。
- 再生中にユーザーが YouTube プレイヤー自体の操作で一時停止した場合は、そのまま待つ。シークして最後まで行った場合は「終わった」として扱う（**私の判断**）。
