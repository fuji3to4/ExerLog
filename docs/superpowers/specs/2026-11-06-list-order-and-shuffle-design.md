# リストの並び替えとシャッフル 設計

日付: 2026-11-06

## 意図と背景

連続再生ができるようになり、ライブラリで「表示中のリスト」をそのまま上から流せるようになった。そうなると次に欲しくなったのが「流す順番」を自分で決めること。

- **自分なりの並びを作りたい**。セット（マイリスト）の中の順番が主目的で、「すべて」も同じ仕組みで並べ替えられるとよい。仕組みはセットと「すべて」で共通にしたい。
- **毎日同じ順番だと飽きる**ので、気分転換に「すべて」などをランダムに流したい。
- ただし、シャッフルや「よく見た順」などで並べ替えたときに、**自分で作った並びが崩れるのは困る**。シャッフル・並べ替えメニューはどちらも「一時的な見せ方」であるべき。

## ゴール

1. ライブラリの編集モードで、表示中のリスト（セット or すべて）の順番をドラッグで並べ替え、保存できる。
2. 並べ替えメニューに「シャッフル」を足す。選ぶと表示中のリストがその場で混ざり、そこから開いた動画はその順で連続再生される。
3. プレーヤーにもシャッフルボタンを置き、ライブラリの「シャッフル」と連動させる。
4. 保存した並び順は、シャッフルや「よく見た順」「よくできた順」では一切書き換わらない。

## 非ゴール

- セット以外のリスト（今日の「おすすめ」など）の並べ替え保存。
- 並び順の複数保存（「並びA／並びB」の切り替え）。
- プレーヤー画面の中での並べ替え（「次は」一覧のドラッグなど）。
- シャッフルの重み付け（あまり見ていない動画を先に、など）。

## アンチゴール（動いても失敗とみなすもの）

- シャッフル・並べ替えメニュー・絞り込みの操作で、保存した並び順が変わってしまう。
- プレーヤーの「次は」に出ている順番と、実際に流れる順番が食い違う。
- プレーヤーでシャッフルしてライブラリに戻ると、ライブラリが違う順番で並んでいる。
- 大きなカードのままドラッグさせる、↑↓ ボタンを何度も押させる（ユーザーは「どちらも操作性が悪い」と明言）。
- 下から出るシート型のメニュー（ユーザー方針: メニューはその場に出るドロップダウン）。
- 濃いベタ塗りのボタン（ユーザー方針: 36px 前後の薄い色の丸いボタン）。

## 決まっている振る舞い（ユーザーと合意済み）

### 並び順の持ち方

- セットも「すべて」も、並び順は「動画 ID を並べたリスト」として同じ形で扱う。並べ替えの操作（UI）も 1 つで、表示中のリストに対して働く。
- 「すべて」の並び順もセットと同じく他の端末へ同期する。
- 並び順に入っていない動画（新しく追加した動画など）は「すべて」の末尾に付く。

### 並べ替えの操作（モックアップ案 B を採用）

- ライブラリの編集モードに「⇅ 並び替え」ボタンを置く（今の「＋ 追加」の並び）。
- 押すと、大きな動画カードのグリッドが **細い行のリスト**（小さいサムネ・タイトル・右端に ≡ ハンドル）に切り替わる。≡ をつかんでドラッグで動かす。
- 「完了」で通常のカード表示に戻る。
- 並べ替えができるのは、検索も絞り込みも効いていないときだけ。一部だけ見えている状態で動かすと、見えていない動画の位置が分からなくなるため。
- 並べ替えメニューが「シャッフル」「よく見る順」などのときに「⇅ 並び替え」を押すと、メニューを「標準」に戻してから並び替えモードに入る（ユーザー指示、2026-11-06）。

### シャッフル（ライブラリ）

- 並べ替えメニュー（「標準」「よく見た順」「よくできた順」）に「シャッフル」を足す。
- 選ぶと、表示中のリスト（すべてでもセットでも）がその場で混ざる。そこから動画を開くと、その順番で連続再生される（ライブラリは見えている順をプレーヤーに渡す既存の仕組みをそのまま使う）。
- 「標準」に戻すと、保存した並び順に戻る。
- シャッフルの順番は、選び直すまで固定。動画を開くたびに混ぜ直さない（「次は」と実際の順番がずれるため）。もう一度混ぜたいときは「シャッフル」を選び直す。

### シャッフル（プレーヤー）と連動

- プレーヤーの連続再生のチップ（🔁 ループ・✓ 自動できた）の並びに、🔀 シャッフルのチップを足す。
- 押すと、いま流れている動画はそのまま続き、残りの動画が混ざる。「次は」の一覧も混ざった順に変わる。もう一度押すと元の順番に戻る。
- ライブラリから開いていた場合、ライブラリに戻ると並べ替えメニューが「シャッフル」になっていて、プレーヤーと同じ順番で並んでいる。
- 逆に、ライブラリで「シャッフル」を選んでから動画を開いた場合は、プレーヤーのシャッフルチップが最初から点いている。
- 「今日」の画面から開いた場合は、ライブラリのメニューとは連動せず、プレーヤーの中の順番だけが混ざる。

### 並べ替えの選択を覚えておく（今の動きからの変更）

- 今のライブラリは、画面に入るたびに並べ替えが「標準」に戻る。これを、**アプリを開いているあいだは並べ替えの選択（とシャッフルの順番）を覚えておく**ように変える（ユーザー了承済み）。プレーヤーとの連動に必要なため。

## 私（Claude）の判断（ユーザーに確認していない）

- **選んでいるセットも一緒に覚える。** シャッフルの連動で「戻ったら同じ順番」を守るには、戻った先で同じリストが表示されている必要があるため。検索語と絞り込みは今まで通り覚えない。
- **プレーヤーでシャッフルを外したときは、シャッフル前の並べ方に戻る**（「よく見た順」から開いていたなら「よく見た順」に戻る）。
- **シャッフルの順番は、絞り込みに関係なくリスト全体（選んでいるセット、または「すべて」）の並びとして作る。** 絞り込み中は、その全体の並びを絞り込んで見せる。検索や絞り込みは今まで通り覚えないので、ライブラリに戻って絞り込みが外れても、プレーヤーで流れていた動画どうしの前後関係はそのまま保たれる（間に、絞り込みで外れていた動画が混ざって見えるだけ）。
- **プレーヤーでシャッフルを入れたときは、いま流れている動画を先頭に置き、それ以外の動画（すでに流し終えた動画も含む）を全部混ぜてその後ろに並べる。** 新しい混ざった順で頭から流し直す扱いなので、ループがオフでも、さっき流した動画がまた出てくることがある。ライブラリに戻ると、いま流れていた動画がリストの一番上に来る。
- **プレーヤーでシャッフルを外したときは、元の順番に戻し、いま流れている動画の元の位置から続ける。**
- **シャッフルの状態は「端末の設定」ではなく、その回のリストに付く。** ループや自動できたのように端末に覚えさせない。ライブラリから開いた場合は、ライブラリの並べ替えメニュー（「シャッフル」かどうか）がそのまま状態になる。「今日」から開いた場合は、その再生のあいだだけ有効で、「今日」から別の動画を開き直すと、シャッフルなしの状態から始まる。
- **シャッフルチップは、連続再生がオンのときだけ出る**。他のチップと同じ扱いにする。
- ドラッグは、すでに依存に入っている `@dnd-kit/core` / `@dnd-kit/sortable` を使う。タッチでのドラッグ（ハンドルをつかんだときだけ動き、他の場所ではスクロールできる）が前提。
- 「すべて」の並び順を保存していないとき（今の全ユーザー）の既定の順番は、今の表示順（内部の ID 順）のまま変えない。

## 前提・制約

- 既存: `ExerciseSet.exerciseIds` が順番を持ち、`resolveSetExercises` がその順で解決する。セットは Google スプレッドシートの `ExerciseSets` タブと同期している（`src/features/sync/sync-config.ts`）。
- 既存: 「すべて」は `listAllExercises()`（`appDb.exercises.toArray()`）の順。保存された並び順はない。
- 既存: ライブラリは `usePublishPlayQueue` で「見えているリストと順番」を sessionStorage に書き、プレーヤーはそれを読んで連続再生する（`src/features/playlist/play-queue-store.ts`）。
- 既存: プレーヤーの設定チップは `src/features/playlist/components/continuous-bar.tsx`、キューは `use-playlist.ts`。
- 「アプリを開いているあいだ覚える」は sessionStorage 相当（タブ／アプリを閉じれば消える）。
- 同期は last-writer-wins。並び順の同期もこれに従う。

## 作る人に任せること

- 「すべて」の並び順を **どこに・どういう形で保存して同期するか**（例: 動画ごとの並び番号を `Exercises` に持たせる／並び順 1 件を持つ専用の同期レコードにする）。条件は、セットと同じ「ID の並び」として UI から扱えること、同期されること、新しい動画が末尾に来ること、既存ユーザーの見た目が変わらないこと。
- シャッフルの状態（オン／オフ、混ざった順、どのリストのものか）を、ライブラリ・プレーヤー間でどう受け渡すか。上の「連動」の振る舞いを満たせば形は問わない。なお今のキュー受け渡し（`exerlog-play-queue`）は「今日」とライブラリが同じキーに書き、どの画面から来たかを持っていないので、出どころ（ライブラリのどのリストか／今日か）を区別できる形に広げる必要がある。
- 細い行リストの細部（サムネの大きさ、ドラッグ中の見た目、並び替え中に絞り込みや他の編集ボタンをどう隠すか）。既存の `ui-style-preferences`（YouTube 風カード、薄い色の丸いボタン）に合わせる。
- 並び替え結果の保存タイミング（ドロップごとに保存か、「完了」でまとめて保存か）。
