# 写真の記録モジュール 設計

日付: 2026-10-27
状態: 承認済み

## 背景と目的

リンパ浮腫患者ネットワークの代表からの声：「写真は撮るけれど、いつ撮って、そのときどうだったかを日記のように一貫して残せると便利」。

記録モジュールの土台（`docs/superpowers/specs/2026-10-27-record-modules-foundation-design.md`、実装済み）の第2段階として、写真の記録モジュールを足す。
土台の設計書には、「写真のモジュールを無理なく受け入れられること」が条件として書かれている。

撮るものの例は、むくんだ腕や脚の見た目、蜂窩織炎の赤み、弾性着衣のあとなど。本人が気になったときに撮る。撮り方の決まりはまだない（代表の声をそのまま伝えたもの）。
受診時に医師・看護師に見せることも想定する（土台の設計書と同じ）。

## ゴール

1. 「＋記録する」のドロップダウンに「写真」が出る。選ぶと、時刻・写真・メモを入れる画面が開く。
2. 1回の記録に、写真を**複数枚**付けられる（ユーザーの判断）。
   - 「📷 撮る」（カメラ）と「🖼 選ぶ」（既存の写真）の両方から足せる。
   - 1枚ずつ「×」で外せる。
   - 上限は20枚（私の判断）。
   - 写真は、足した順に並ぶ。
3. 修正の画面でも、写真の追加・削除とメモ・時刻の変更ができる。
4. タイムラインのカードに、小さな写真（最初の数枚）と枚数とメモを出す。
5. 履歴の「写真」チップでは、1記録＝1カードを時刻の新しい順に並べる。カードの中で、写真は**横一列**に並び、多いときは横にスクロールする（案A。ユーザーの判断）。
6. 写真を押すと全画面で大きく表示し、同じ記録の写真を左右にめくれる。閉じるボタンと Esc で閉じる。
7. 写真は端末の中（IndexedDB）に保存する。保存するときに、JPEG・長い辺1600pxまでに縮小する（私の判断）。
8. Google連携をしている人の写真は、Googleドライブのアプリ専用フォルダに保存する。
   - 設定画面の「Google連携」の欄に、「写真を同期する」のチェックボックスを置く。最初はON（ユーザーの判断）。
   - 写真の日時・メモ・写真の並びと参照は、チェックに関係なく、スプレッドシートの新しいタブに同期する。
9. 期間のまとめに「写真」のカードを出す。期間内の写真の記録を時刻順に、横一列で並べる（土台の設計書の想定）。記録がなければ「記録なし」。
10. 写真の記録の CSV 書き出しには、日付・時刻・メモ・枚数だけを入れる（写真そのものは入れない。私の判断）。

## ゴールではないもの

- 部位ごとの並べ比べ、前回の写真と左右に並べる比較、写真の上への書き込み・切り抜き。「写真とメモを時間順に表示するだけで十分」（ユーザーの言葉）。
- 写真の印刷・PDF 化・共有。
- 同期の通信を Wi-Fi のときだけに限ること（ブラウザから確実に判定できないため）。通信量が気になる人は、チェックを OFF にする。
- アプリ全体のロック（パスコードなど）。

## 決めたこと

### データの形

- **写真の記録**：`id`、`date`、`recordedAt`（必須）、`note`、`updatedAt`、写真の並び（写真の id の配列）。
- **写真そのもの**：記録とは別のテーブルに、写真1枚ずつ保存する。
  - 中身：`id`、どの記録のものか、縮小した JPEG の Blob、幅・高さ。
  - ドライブのファイル id は、まだなければ空にする。
  - 同期の状態を持つ。たとえば「端末にだけある」「ドライブにも上げた」「ドライブにだけあり、端末には未取得」。
- テーブル名、型名、状態の値は builder に任せる。Dexie はバージョンを1つ上げて、必要なテーブルを足す（下の「ドライブのファイルの対応表」と「ゴミ箱へ移す待ち行列」を含む）。既存のテーブルには手を付けない。

### スプレッドシートとドライブ

- **シート**：タブを2つ新しく作る（私の判断）。
  - `Photos`：写真の記録。列は `id`・`date`・`recordedAt`・`note`・`updatedAt` と、写真の並び（写真の id の配列）。詰め方（JSON を1つのセルに入れるなど）は builder に任せる。tombstone の `table` も `Photos`。
  - `PhotoFiles`：写真1枚ごとの「ドライブのファイルの対応表」。列は写真の id・記録の id・ドライブのファイル id・`updatedAt`。
  - 分ける理由：アップロードが終わってファイル id を書き込むことを、記録の編集と別の行にする。こうすると、ある端末のアップロードが、別の端末でのメモや写真の並びの編集を上書きしない（どちらも、いまの「新しいほうが勝つ」同期のまま扱える）。
- **ドライブ**：アプリが作る専用フォルダ「記録写真」に、写真1枚＝1ファイルで置く。フォルダ名・ファイル名にアプリ名（Lymly は仮称）を入れない（ユーザーの指示）。
  - 許可はいまの `drive.file`（このアプリが作ったファイルだけに触れる）のまま足りる。利用者に新しい許可は求めない（調べて確認済み）。
- **フォルダの見つけ方**：初回に専用フォルダを作り、その id を端末に覚える。フォルダには作るときに目印（Drive の `appProperties`）を付け、別の端末ではその目印で探す。名前では探さないので、アプリ名やフォルダ名が変わっても、利用者がドライブ上で名前を変えても同じフォルダが見つかる（私の判断）。目印付きのフォルダが複数見つかったら、いちばん古いものを使う。
- **アップロード**：「写真を同期する」が ON で Google 連携中のとき、いつもの同期のついでに、ドライブに未アップロードの写真を上げる。上げたら `PhotoFiles` に行を足す。
  - チェックを OFF から ON に戻したときは、OFF の間に撮った写真もまとめて上げる（私の判断）。
- **別の端末での取得**：記録の写真が端末にないときは、その写真を画面に出すときに、`PhotoFiles` のファイル id を使ってドライブから取ってきて保存する（私の判断）。
  - 取得中は「読み込み中」を出す。
  - ファイル id がまだない（元の端末がまだ上げていない）ときは「まだアップロードされていません」を出し、次の同期のあとにまた試す。
  - Google にログインしていない・期限切れのときは「Googleにログインすると表示できます」を出す。ログインを促す画面は出さない。
  - 通信に失敗したときは「取得できませんでした」を出し、次に表示したときにまた試す。
  - 「写真を同期する」が OFF でも、すでにドライブにある写真の取得はしてよい（私の判断）。
- **削除**：記録を消したら、その写真のドライブのファイルもゴミ箱へ移す（完全には消さない。Google ドライブ側で戻せる。私の判断）。
  - 修正で外した写真も同じく、ドライブのファイルをゴミ箱へ移す。
  - 「すべての記録を削除」も、土台の仕組みどおり写真を含めて消し、同じくゴミ箱へ移す。
  - 別の端末で消された記録（tombstone で届く）は、その端末の写真も消す。ドライブのゴミ箱へ移すのは、消した側の端末の役目とする。
  - **ゴミ箱へ移すのは確実に行う**（私の判断。体の写真がドライブに残り続けないようにするため）。
    - 消すときに、ドライブのファイル id を「ゴミ箱へ移す待ち行列」に入れる。
    - 同期のたびに待ち行列を処理し、成功したものだけ消す。オフラインや失敗のときは次の同期でやり直す。すでに無いファイル（404）は成功とみなす。
    - 待ち行列への追加は、記録を消すのと同じトランザクションで行う（土台の `clearAll()` の決まりに合わせる）。
- **チェックを OFF にしたとき**：それ以降は上げない。すでにドライブにある写真には手を付けない（私の判断）。ゴミ箱へ移す待ち行列は OFF でも処理する。
- **チェックの保存先**：この端末の中だけ（いまの Google 連携の設定と同じ扱い）。

### 土台の仕組みへの足し方

- 土台の同期は「表＝シートのタブ」だけを同期する（`RecordModuleData.syncConfigs`）。写真には、それとは別に「ファイルを上げる・消す」手順が要る。
- `RecordModuleData` に、モジュールがファイルの同期を持てる任意の入り口を1つ足す（例：表の同期の後に呼ばれる関数）。土台の同期処理は、その入り口を持つモジュールについてだけ呼ぶ。名前と形は builder に任せる。
- 体調・身体・周径には、この入り口は要らない。
- 写真モジュールのフォルダは、ほかのモジュールのフォルダを import しない（土台の決まり）。

### 端末のデータが消えないようにする

- iPhone の Safari などは、しばらく開いていないサイトのデータを消すことがある。アプリの起動時に、ブラウザに「データを消さないでほしい」と頼む（`navigator.storage.persist()`）。失敗しても何もしない。
- 設定画面の「写真を同期する」の近くに、短い注意書きを出す。文言の案：「OFFにすると、写真はこの端末の中にだけ保存されます」。

### 画面

- **入力画面**：たたき台 `.superpowers/brainstorm/938-1793078121/content/photo-record.html` の左側のとおり。
  - 時刻、写真の小さな一覧（「×」付き）、「＋追加」、「📷 撮る」「🖼 選ぶ」、メモ、保存。
  - 撮る・選ぶは `<input type="file" accept="image/*">` を使う。撮るのほうは `capture` を付ける。
  - 選ぶのほうは、一度に複数選べること。
- **写真のない保存**：写真が0枚の記録は保存できない（保存ボタンを押せない）。
- **縮小中の表示**：縮小処理の間は、追加した写真の枠に「処理中」を出す。
- **縮小できない画像**：読めない画像（HEIC で読めないなど）は、その1枚だけ「読み込めませんでした」として外す。
- **アイコンと色**：アイコンは lucide の `Camera`。タイムラインの点の色は builder が決める（既存の3色と区別できること）。

### i18n

- 表示名は「写真」。説明は「写真とメモ」。
- 編集画面の見出しは「写真の記録を編集」。新規は、土台の「{module}を記録」の形で「写真を記録」になる。
- 設定のチェックは「写真を同期する」。
- ja と en の両方に足す。

## builder に任せること

- テーブル名、型名、同期状態の値、シートの写真の並びの詰め方。
- 縮小の実装（`createImageBitmap` と `OffscreenCanvas`、または `<canvas>`）と、JPEG の画質（0.8 前後）。
- ドライブのフォルダの作り方と探し方（初回に作り、ファイル id を端末に覚える。消えていたら作り直す）。
- アップロードの並び（1枚ずつか、少しずつ並行か）と、失敗したときの再試行。次の同期でやり直せればよい。
- 全画面表示の部品。Radix の Dialog を使ってよい。
- 写真の Blob を画面に出すときの `URL.createObjectURL` と、その後片付け。
